The class rhythm is "prepare → predict → run → compare". Finish 1-0 / 1-A / 1-B before Session 2. Each notebook's setup cell writes the default files that notebook needs; it does not carry over changes from another runtime.

The real outputs from before the materials were rebuilt are kept in [output-history](output-history/README.md), together with the code and form values of that time. These snapshots are for checking historical results; they are not evidence that the new code has been run.

- 2-A: in class, do A first and change only the request to see which handbook is picked; then do B, keeping the handbook fixed and changing the body. C, keeping the request fixed and changing the description, is optional. Change one thing at a time.
- 2-B: first look at the homework and find the problems, then compare text, an agent choosing a script, and the workflow running it directly. Getting the same result is also a valid observation.
- 2-C: predict first, then compare with and without tool permissions, and use the tool log and the reply to find the malicious line; only fake keys are used.
- 2-D: the main line tells apart resuming an unfinished thread, retrieving a finished result, and a fresh run on a new thread; the pure agent and the eval are optional.
- 2-E, and every part marked "supplementary / optional", are not counted in the in-class main line.

Before re-running a part, read its prerequisites; a setup cell may overwrite the handbooks. When a runtime is reclaimed, the files in `/content/` are not kept; save a copy of the notebook and a backup of the handbooks / code / checkpoint separately.
