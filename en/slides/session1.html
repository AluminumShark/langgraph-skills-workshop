Component 2: Node, one workstation

def check_syntax(state):    ok, error = parse_syntax(state["code"])  # grammar only, runs nothing    # return only the boxes this node owns    return {"syntax_ok": ok, "error": error}
  • A Node is just a function: takes a dict, returns a dict
  • It returns only the boxes it owns (for check_syntax: syntax_ok and error), and LangGraph writes them back to the order slip for you [4]

# Wrong waydef bad_node(state):    state["syntax_ok"] = True   # scribbles over the whole order slip    return state      # hands back the whole slip: boxes written by other stations get rewritten too # Right waydef good_node(state):    return {"syntax_ok": True}   # hand back only the box you changed

Models & ToolsWorkflowAgent21 / 48
A Node is just a function: it takes a dict and returns a dict. The key point is that it returns only the box it owns, and LangGraph writes it back to the order slip [4]. The clerk who seals only stamps "sealed" and never changes the sweetness. Common mistake: editing state directly and handing back the whole thing rewrites every box, so what other stations wrote may be overwritten. For boxes that "keep appending" (for example messages, the conversation log in the appendix), this can produce unexpected merges; the behavior depends on the reducer and message IDs. The right way is to return only the box you changed and let LangGraph merge it. The "syntax check" in check_syntax only looks at grammar; it does not run the code.

Plain edge: after A, always B

The math of ten checkpoints

Assume the checks are independent: each passes 99% of the time → all ten pass about 90%(0.99 to the 10th power)

Each passes 95% of the time → all ten pass only about 60%(0.95 to the 10th power) [9]

Common mistake: a custom State with no merge rule
class BadState(TypedDict):    messages: list   # ← the default behavior is "overwrite" def bad_chatbot(state: BadState) -> dict:    response = model.invoke(state["messages"])    return {"messages": [response]}   # overwrites the whole list r1 = bad_graph.invoke({    "messages": [{"role": "user", "content": "My name is Alex"}]})print(len(r1["messages"]))
1   ← Odd! The user message "My name is Alex" is gone
Fix: tell it this box should be merged
class GoodState(TypedDict):    messages: Annotated[list, add_messages]
  • How to read this line: messages is a list, but LangGraph should not overwrite it; it merges with add_messages (a new ID is added, the same ID is updated)
  • Memory aid: the first slot of Annotated is the type, the rest is extra information; LangGraph uses it to set the merge rule (the built-in MessagesState used in 1-B is defined this way)
  • Remember "with history vs. without history"? If the conversation box is overwritten, the model forgets who you are

Optional appendix: the core model-and-tool loop

from langchain_core.messages import SystemMessagefrom langgraph.graph import START, MessagesState, StateGraphfrom langgraph.prebuilt import ToolNode, tools_condition tools = [run_code, check_indent, read_spec]model_with_tools = model.bind_tools(tools) def ask_model(state: MessagesState) -> dict:    messages = [SystemMessage(system_prompt)] + state["messages"]    return {"messages": [model_with_tools.invoke(messages)]} builder = StateGraph(MessagesState)builder.add_node("ask_model", ask_model)builder.add_node("tools", ToolNode(tools))builder.add_edge(START, "ask_model")# tools_condition: if the last message has tool_calls go to tools, otherwise go to ENDbuilder.add_conditional_edges("ask_model", tools_condition)builder.add_edge("tools", "ask_model")  # after tools finish, loop back to ask_model expanded_agent = builder.compile()
