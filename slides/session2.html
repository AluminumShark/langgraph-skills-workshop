RAG （Retrieval-Augmented Generation）＝ 先查再答：從一大堆資料裡搜尋出最相關的幾段，放上桌給 AI 參考，再讓它回答。
Tool：「查」這個動作search_past_mistakes(query)回傳最像的幾筆歷屆作業錯誤。
資料不多、只有自己用 → 本地 @tool 就夠

agent 用起來和本地 tool 一模一樣

Send：在流程裡說「這個節點，照這份清單一份開一個」，LangGraph 會同時跑它們。

第四站說 200 份要同時批，每份開一個子 agent。在 LangGraph 裡做法是 Send：條件邊的函式回傳一串 Send，每個 Send 帶一份作業，LangGraph 會把「批一份」這個節點同時開很多個 [14]。

上雲端要多想兩件事：一是並行上限，config 的 max_concurrency 可以限制同時跑幾個，模型供應商也有每分鐘的上限；LangSmith Deployment 這類平台另外有任務佇列幫你排隊 [11]。二是成本：Anthropic 的數字是多 agent 約 3 到 10 倍 token [6]，先量一份作業花多少，再乘以 200，確定付得起再開。
